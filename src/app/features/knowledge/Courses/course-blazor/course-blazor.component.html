Blazor Deep Dive: From Beginner to Advanced

Co je Blazor

Blazor je component-based C# SPA application framework.

Render režimy

Blazor má dnes 3 hlavní režimy renderování:

  • Static SSR – čisté server renderování. Vyrenderuje se jen HTML, bez interaktivity.
  • Interactive Server – komunikace klienta s backendem běží přes SignalR / websocket. Posílají se rozdíly v DOM.
  • WebAssembly – tlustý klient. Do browseru se pošlou soubory s C# kódem a runtime.

HTTP request → Blazor UI pipeline

app.MapRazorComponents<App>()

HTTP request na UI skončí zde. Odtud se vyrenderuje root komponenta App.razor.

Soubory

  • App.razor – HTML shell celé aplikace.
  • Routes.razor – přes to jdou požadavky na komponenty k zobrazení, layouty a 404 stránka.

Blazor tagy

  • <Routes /> – router outlet. Podle URL se sem vloží stránka / komponenta s @page.
  • <HeadOutlet /> – umožňuje dynamicky měnit <head>, title, meta a linky.
  • <ImportMap /> – mapa JS modulů pro prohlížeč, nutná pro načtení Blazor JS runtime.
  • <ResourcePreloader /> – performance optimalizace. Vygeneruje <link rel="preload"> pro Blazor assety a zrychluje start.

Komponenty

  • Routovatelné komponenty – page components, mají @page.
  • Neroutovatelné komponenty – části stránek.
@attribute [StreamRendering]

V SSR umí streamovat data / renderování komponenty po částech.

Atributy

  • [Parameter] – parametr komponenty, často routovatelný, bere se z parentu nebo z routy.
  • [SupplyParameterFromQuery] – bere hodnotu z query stringu, například ?id=123.
  • [SupplyParameterFromForm] – binduje data z formuláře na field / property.

Lifecycle & hooks

  1. Construct
    • Instantiation
    • SetParametersAsync – before the params are set
  2. Initialize
    • OnInitialized() – při vytvoření komponenty
  3. Receive parameters
    • OnParametersSetAsync() – při změně parametru, případně můžu override v code-behind.
  4. Render
    • OnAfterRenderAsync(bool firstRender)
    • ShouldRender
    • Dispose
  5. Destruct

Nová instance se vytvoří, když opustíš stránku, vrátíš se na ni, nebo když ji vynutíš klíčem @key.

První se triggernou neasync verze a pak až async verze.

Problém

Při SSR + prerenderingu se každá komponenta může vytvořit 2×: jednou při GET requestu a podruhé při navázání SignalR spojení.

Řešení

  1. OnAfterRender(bool firstRender) – workaround pro věci, které chci pustit až po renderu.
  2. V OnInitialized() si ohlídat interaktivní režim. 
protected override void OnInitialized()
{
    if (renderInfo.IsInteractive)
    {
        // Tady se to zavolá až při interaktivním SignalR spojení,
        // ne při prvním GET requestu
    }
}

Interactive Server

Program.cs

builder.Services.AddRazorComponents()
    .AddInteractiveServerComponents();

app.MapRazorComponents<App>()
    .AddInteractiveServerRenderMode();

Globální zapnutí IS

<Routes @rendermode="InteractiveServer" />

Lokální zapnutí IS

<ServerComponent @rendermode="InteractiveServer" />

Doporučení: ne všechno musí být Interactive Server. Některé stránky můžou zůstat SSR. 

@attribute [ExcludeFromInteractiveRouting]

Na page komponentě udělá výjimku z interaktivního routování.

Input / Output mezi komponentami

Input

[Parameter]
public string? Property { get; set; }

Parent nastaví hodnotu při vstupu do komponenty. Na změny můžu reagovat třeba v OnParametersSet().

Output

V child komponentě:

[Parameter]
public EventCallback<T> CallbackName { get; set; }

private async Task OnSomethingChanged(T value)
{
    await CallbackName.InvokeAsync(value);
}

V parent komponentě:

<ChildComponent CallbackName="HandleMethod" />

Reference na child komponentu

<CityListComponent @ref="cityListComponent" />
private CityListComponent? cityListComponent;

Cascading value

<CascadingValue Name="SelectedCity" Value="@selectedCity">
    ...
</CascadingValue>

Předá selectedCity všem child komponentám, které si to můžou chytit takto: 

[CascadingParameter(Name = "SelectedCity")]
public string? SelectedCity { get; set; }

Přes hranici SSR → InteractiveServer nejde použít cascading value. Tam je lepší posílat data normálně přes parametry.

Static assets fingerprint

Od .NET 10 hash ke statickým věcem jako CSS, JS atd.

Hydratace

Hydratace = připojení HTML v prohlížeči k živé komponentě, jejíž .NET runtime běží na serveru. Typicky v Interactive Server.

Virtualizace v Blazoru

Nevyrenderují se všechny položky seznamu, ale jen ty, které jsou vidět. Je to takový chytrý foreach, který do DOMu dává jen viditelné položky. 

<Virtualize Items="Items" Context="item">
    <div>@item.Name</div>
</Virtualize>

Prerendering

Prerendering je zapnutý defaultně v Interactive Server i ve WebAssembly. Stránka se poprvé vyrenderuje na serveru a pak pokračuje interaktivní část.

Render

Kdy se komponenta přerenderuje:

  • při prvním renderu
  • při změně parametru
  • při změně CascadingParameter
  • po Blazor eventu (@onclick, @onchange, ...)
  • po zavolání StateHasChanged()
  • po dokončení některých async lifecycle metod

Render neproběhne, když ShouldRender() vrátí false.

Pokud je parametr komplexní / mutable typ, child komponenta se většinou přerenderuje vždy.

  • buď použít ShouldRender()
  • ale hlavně tehdy, když je render drahý nebo se parent často mění

InvokeAsync v Blazoru zařadí tvoji akci do správné fronty / kontextu rendereru, aby se bezpečně provedla práce s komponentou a případný render.

[PersistentState] je atribut pro jednorázové předání dat ze serveru do klientské Blazor části při startu aplikace.

Události

  • @onclick
  • @onchange – až při ztrátě focusu prvku
  • @oninput – hned jak se změní hodnota
  • @bind-value="property" – v inputech apod.
  • @bind-Value="property" – u komponent a ve formulářových scénářích
  • @key – mapování ve foreach podle identity

Routing and navigation

  • Static routing – každý požadavek = HTTP request.
  • Interactive routing – první request je statický, každá další navigace může běžet přes SignalR.
  • WebAssembly – routing i navigace se řeší na klientovi, bez nutnosti posílat každý přechod na server. Server se používá hlavně pro data a API volání. 
<NavigationLock OnBeforeInternalNavigation="ConfirmLeave" />

Použiješ, když se chceš uživatele zeptat, jestli opravdu odejít ze stránky.

State management

1) Přes URL

Route parametr:

/product/{id:int}

Navigace:

NavigationManager.NavigateTo("/product/5");

Query string:

/products?page=2&filter=shoes
[SupplyParameterFromQuery]

2) localStorage / sessionStorage

Spíš na persistenci stavu, ne jako hlavní univerzální řešení.

Ukládání může být přes injectovanou storage service.

3) State management přes service / state container

Třída zaregistrovaná do DI, obvykle jako AddScoped. Ve WebAssembly často spíš singleton. Pak se injectuje do komponent a sdílí stav napříč aplikací.

Observer pattern

  • Komponenta se přihlásí na event (OnChange += ...), takže poslouchá změny.
  • Když se ve AppState něco změní, zavolá se OnChange?.Invoke().
  • Tím se spustí handler, který zavolá StateHasChanged().
  • Výsledek: komponenta se znovu překreslí s novými daty.
