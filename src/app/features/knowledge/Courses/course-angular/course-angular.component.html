Input / Output / Signály

Input

@Input() result: number;

Předání hodnoty potomkovi.

Nově přes signály:

results = input<number>();
title = input.required<string>();

input.required znamená, že hodnota musí být dodaná v šabloně. 

<app-results [results]="calcResults"></app-results>

Output

@Output() calculate = new EventEmitter<number>();

Předání události nebo hodnoty rodiči.

Nově:

calculate = output<number>();
onSubmit() {
  this.calculate.emit(42);
}
<app-user-input (calculate)="onCalculateInvestmentResults($event)"></app-user-input>

Two-way binding

[(ngModel)]="propertyInModel"

Two-way binding mezi šablonou a modelem.

Nově lze použít i model signál:

value = model<string>();

Computed

property = computed(() => this.signal())

Díky computed se hodnota přepočítá vždy, když se změní signal uvnitř.

Readonly signal

const allTasks = tasks.asReadonly();

Readonly pohled. Převede writable signal na readonly signal.

Update a mutate

tasks.update((oldValue) => oldValue + newValue);

Updatuje signal. Dostanu starou hodnotu a vracím novou referenci.

todos.mutate(arr => arr.push('new task'));

Změní obsah pole bez nové reference. Používat opatrně.

Signal z Observable

tasks = selectSignal(this.store.select(selectTasks));

Readonly signal z Observable, speciálně pro NgRx Store.

tasks = toSignal(this.store.select(selectTasks), { initialValue: [] });

Signal z Observable. Je potřeba mít initial value.

ng-content

<ng-content select=".icon"></ng-content>

Mohu sem vložit obsah z rodiče. Přes select vybírám přesně, co se má vložit. 

<span class="icon">→</span>
<ng-content select="input, textarea"></ng-content>

Mohu vybrat i více typů prvků.

Selector komponenty / direktivy

selector: 'button[appButton]'

Pak použiji button s atributem appButton, aby v DOM nebylo něco jako vlastní obal navíc.

Template reference variable

#titleInput

Template reference variable. Mohu ji použít v šabloně nebo poslat do metody.

HTML binding

<div [class.status]="currentStatus === 'offline'"></div>

Když je podmínka true, přidá se class status.

Dynamické přiřazení tříd

<div
  [class]="{
    status: true,
    'status-online': currentStatus === 'online',
    'status-offline': currentStatus === 'offline',
    'status-unknown': currentStatus === 'unknown'

Pomlčka v názvu class se píše do uvozovek.

Lifecycle

  • ngOnInit – po constructoru, když už jsou inicializované inputy a další věci
  • ngOnChanges – při změně inputů
  • ngDoCheck – při každé kontrole změn; moc se nedoporučuje, protože se spouští často
  • ngOnDestroy – než je komponenta zničena

Novější přístup přes DestroyRef

private destroyRef = inject(DestroyRef);

this.destroyRef.onDestroy(() => {
  // něco udělej při zničení komponenty
});

ViewChild

@ViewChild('form') form?: ElementRef<HTMLFormElement>;

Vyberu ze šablony prvek do proměnné. Obecně spíš nepoužívat zbytečně, protože to obchází běžný Angular přístup.

Od Angular 17 nově:

private form = viewChild.required<ElementRef<HTMLFormElement>>('form');

Tohle vrací signal-like přístup.

effect

effect(() => {
  console.log('Counter je teď:', this.counter());
});

Spustí se vždy, když se změní signal použitý uvnitř. Často se dává do constructoru.

Direktivy

Direktiva = přidání vlastností nebo chování prvku.

Custom attribute directive

@Directive({
  selector: 'a[appSafeLink]',
  standalone: true,
  host: {
    '(click)': 'onConfirmLeavePage($event)'
  }
})

Structural directive

Například *ngIf. Mění DOM.

*ngIf se interně překládá na ng-template.

Pipes

Pipes slouží pro formátování a transformaci hodnot v šablonách.

@Pipe({
  name: 'temp',
  standalone: true
})
export class TemperaturePipe implements PipeTransform {
  transform(value: number) {
    return value;
  }
}

Services

Service = logika pro více komponent.

@Injectable({
  providedIn: 'root'
})
export class TasksService {
}

providedIn: 'root' znamená, že službu mohu injectovat kdekoliv v aplikaci.

Další scope může být třeba konkrétní komponenta nebo jiný injector scope.

Change Detection

Angular standardně používá zone.js.

  • v default režimu Angular kontroluje změny při různých událostech
  • v debug režimu se některé věci mohou tvářit, že běží 2×

Vyjmutí z change detection

private zone = inject(NgZone);

this.zone.runOutsideAngular(() => {
  // kód mimo Angular change detection
});

OnPush

Do komponenty mohu dát ChangeDetectionStrategy.OnPush.

Pak reaguje hlavně na změnu inputu, event nebo ruční označení změny. 

ChangeDetectorRef.markForCheck()
ChangeDetectorRef.detectChanges()

Signály

Pokud komponenta používá hlavně signály, změny se vyhodnocují přes ně.

Od novějších verzí Angularu jde jít víc směrem bez zone.js.

RxJS

RxJS = observables.

import { map, tap, catchError, of } from 'rxjs';
  • subscribe() – přihlásím se k odběru Observable, nebo to převedu přes toSignal
  • pipe() – dovolí řetězit operátory

Operátory

map(a => a * 2)

Podobné jako select v C#. Nemění původní data, vrací novou hodnotu. 

tap(v => console.log('Before map:', v))

Nemění data, jen na ně „koukne“ a provede vedlejší akci.

catchError((err) => throwError(() => new Error('Error happened')))

Když nastane chyba, vyhodí novou chybu s vlastním textem.

takeUntilDestroyed(this.destroyRef)

Automatický unsubscribe při zničení komponenty. U signalů si to Angular většinou řeší sám. 

of(value)

Udělá z hodnoty Observable a emituje ji.

Subjecty

Subject je speciální druh Observable, který je zároveň Observer. Hodnoty emituji ručně přes .next().

  • Subject – nic nedrží, jen emituje, co pošlu. Nový subscriber nedostane staré hodnoty.
  • BehaviorSubject – drží poslední hodnotu a novému subscriberovi ji hned pošle.
  • ReplaySubject – drží posledních N hodnot a pošle je novému subscriberovi.
  • AsyncSubject – emituje až poslední hodnotu při dokončení přes complete().

NgRx

NgRx = state management solution.

ng add @ngrx/store

V bootstrap konfiguraci typicky:

provideStore(...)
provideRouterStore()
provideStoreDevtools()
provideEffects([...])

Mapovací strategie

  • mergeMap – pustí všechny requesty zároveň
  • concatMap – pustí je postupně za sebou
  • switchMap – zruší předchozí a nechá jen poslední
  • exhaustMap – pustí první a další ignoruje, dokud nedoběhne

HTTP Requests

private httpClient = inject(HttpClient);

Angular HttpClient. Je potřeba ho providnout, typicky v main.ts. 

this.httpClient.get<any>('http://localhost:3000/places')
  .subscribe({
    error: (err) => {
      this.error.set(err);
    },
    next: (places) => {
      this.places.set(places);
    },
    complete: () => this.isFetching.set(false)
  });

Mohu přidat interceptor, například na auth hlavičku, logování a podobně.

Forms

Základní submit

<form (ngSubmit)="onSubmit()"></form>

(ngSubmit) přepíše defaultní HTML odeslání formuláře.

Stavy polí

  • pristine – pole se ještě nezměnilo od svého inicializačního stavu
  • touched / untouched – uživatel na pole klikl / neklikl
  • dirty – uživatel změnil hodnotu pole oproti původní

1) Template-driven forms

<form #form="ngForm" (ngSubmit)="onSubmit(form)"></form>

Méně používané. Inputy mají name a ngModel.

Importy: FormsModule. Validaci dávám přes atributy nebo direktivy v šabloně.

2) Reactive Forms

Udělám FormGroup a jednotlivé prvky FormControl, pak je nabinduji do šablony.

Importy: ReactiveFormsModule.

form = new FormGroup({
  email: new FormControl(''),
  password: new FormControl<string | null>(''),
  source: new FormArray([
    new FormControl(false),
    new FormControl(false)
  ])
});
<form [formGroup]="form" (ngSubmit)="onSubmit()">
  <input id="email" type="email" formControlName="email" />

  <div formArrayName="source">
    <input type="checkbox" formControlName="0" />
    <input type="checkbox" formControlName="1" />
  </div>
</form>

Ve FormGroup mohu mít i další vnořené FormGroup, aby byla struktura přehledná.

Validace

email: new FormControl('', {
  validators: [Validators.required, Validators.minLength(6)]
})

Pak kontroluji valid nebo invalid na prvku nebo na celém formuláři.

AsyncValidator

Asynchronní validační operace, například volání backendu. Vrací Observable.

Vlastní validator

Když vrátím null, je to validní. Jinak vracím error objekt. 

function mustContainQuestionMark(control: AbstractControl) {
  if (control.value?.includes('?')) {
    return null;
  }

  return { error: true };
}

setValue vs patchValue

  • setValue() – nastaví hodnoty pro celý form
  • patchValue() – mohu nastavit jen část hodnot

Routing

V main.ts povolím routing:

providers: [provideRouter(routes)]

Pak definuji routes:

export const routes: Routes = [
  {
    path: '',
    component: NoTaskComponent
  },
  {
    path: 'users/:userId',
    component: UserTasksComponent,
    title: 'Title na záložce',
    children: [
      {
        path: '',
        redirectTo: 'tasks',
        pathMatch: 'full'
      }
    ]
  },
  {
    path: '**',
    component: NotFoundComponent
  }
];

V šabloně:

<router-outlet></router-outlet>
<a [routerLink]="['/users', user()?.id]" routerLinkActive="selected"></a>

Hodnota z URL v komponentě

  • withComponentInputBinding – automaticky nabinduje hodnoty z URL do inputu stejného názvu
  • ActivatedRoute – ručně si vytáhnu data z paramMap 
private activatedRoute = inject(ActivatedRoute);

V child route to není vždy automatické, tam se řeší konfigurace routeru nebo práce s route stromem.

Navigace

<a routerLink="../">Cancel</a>

Přesun o úroveň výš.

private router = inject(Router);

this.router.navigate(['/users', this.userId(), 'tasks']);

Route Guards

Dávají se do nastavení route.

  • canMatch
  • canActivate
  • canDeactivate

Guard vrací typicky true, false nebo redirect.

Když vrátí false nebo redirect, route se nepustí nebo přesměruje jinam.

Lazy Loading

Lazy loading = kód se nahrává až když je potřeba. Tím stáhnu méně kódu při startu aplikace.

1) Route-based lazy loading

loadComponent: () =>
  import('../tasks/tasks.component').then(mod => mod.TasksComponent)
provideRouter(routes, withPreloading(PreloadAllModules))

Stáhne hlavní bundle a další části dotahuje postupně.

2) Deferrable Views

Od Angular 17.

@defer (on viewport) {
  <app-welcome />
} @placeholder {
  <p>We have offer</p>
}
  • on viewport – načte se, až když se blok dostane do viewportu
  • on interaction(el) – až když uživatel klikne nebo fokusne prvek
  • on hover(el) – při najetí myší
  • on idle – až když je prohlížeč v klidu
  • on timer(2000) – po daném čase
  • on immediate – hned po prvním renderu, ale pořád jako samostatný chunk

Hints

  • Jakýkoliv prvek jako FormGroup, FormArray nebo Routes si mohu udělat bokem v metodě a pak ho vrátit tam, kde ho potřebuji.
  • Angular zničí komponentu, když se změní pevná část URL. Když se změní jen dynamická část, tak ji většinou nezničí.
  • Do eager části neimportovat nic z lazy složek.
  • Sdílené věci dávat do shared, například models, enums nebo services.
