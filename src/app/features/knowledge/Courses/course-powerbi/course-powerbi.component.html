DirectQuery není jen pro SQL zdroje. Používá se tehdy, když nechci data importovat, ale dotazovat zdroj za běhu reportu.

Power Query je nástroj na extrakci, transformaci a nahrání dat, tedy ETL. V Power Query se používá jazyk M pro transformační logiku.

DAX

DAX = logika nad datovým modelem.

Slouží k tvorbě vlastních výpočtů v Power BI.

Míra / Measure

Míra je výpočet v jazyce DAX.

Řádkový kontext / filtrační kontext

Při práci s jazykem DAX je důležité pochopit pojem kontext výpočtu, který určuje, v jakém prostředí se daný výpočet vyhodnocuje.

Kontext má zásadní vliv na to, jak DAX pracuje s daty a jaký výsledek vrátí.

Copilot

Vedle klasického Q&A dnes v Power BI hodně vstupuje i Copilot, který umí pomáhat s analýzou, tvorbou DAXu a prací nad modelem.

Power Query Editor

  • join na sloupce podle společného ID
  • odfiltrování dat přes šipku na sloupci
  • přejmenování sloupců
  • úprava datových typů přes pravé tlačítko na názvu sloupce
  • odstranění duplicit – Odebrat řádky → Odebrat duplicity
  • seřazení dat
  • seskupení dat – Transform → Group By

Když chci seskupovat a zároveň si nechat původní hodnoty, často si předtím sloupec nebo tabulku duplikuji.

Menu

  • Recent sources / zdroje dat
  • Transform data – otevře ETL vrstvu v Power Query Editoru

V horním menu Power Query je možnost Use First Row as Headers, když chci první řádek použít jako hlavičku.

Poznámky k modelu

Když chci, aby AI a Q&A fungovaly dobře, musím mít:

  • dobře pojmenované sloupce
  • dobře pojmenované tabulky
  • rozumné vztahy mezi tabulkami
  • čistý datový model

Jinak se Power BI nebo Copilot hůř orientuje a výstupy jsou méně přesné.

Hints

  • Power Query = ETL nad daty
  • DAX = výpočty nad datovým modelem
  • Measure je výpočet, ne fyzický sloupec v datech
  • Nejdřív si udělat čistý model, až pak psát složitější DAX
  • AI funkce fungují líp, když jsou dobře pojmenované sloupce a tabulky
  • DirectQuery je dobrý, když nechci import, ale bývá citlivý na výkon zdroje
