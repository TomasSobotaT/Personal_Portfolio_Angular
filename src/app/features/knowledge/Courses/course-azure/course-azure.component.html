On-premise vs Cloud

On-premise = CapEx, tedy kapitálové náklady.

Cloud = OpEx, tedy operativní náklady.

Dělení podle toho, co spravuje poskytovatel a co já

  • IaaS – Infrastructure as a Service – dostanu infrastrukturu a všechno ostatní si instaluji a spravuji sám.
  • PaaS – Platform as a Service – dostanu kompletní platformu pro běh aplikací.
  • SaaS – Software as a Service – například Office, GitHub a další hotové služby.

Regiony a zóny

  • Region – geografická oblast, kde má Microsoft svá datacentra.
  • Zone – každá zóna má vlastní datacentrum s nezávislým napájením, chlazením a sítí.
  • Paired Regions – regiony, které automaticky replikují data do partnerského regionu. V případě katastrofy může partnerský region nahradit původní.

Jak vybrat region

  • podle lokace cílového publika
  • podle služeb, které jsou v něm dostupné, protože v každém regionu nejsou všechny služby
  • podle ceny, protože každý region může mít jiné ceny

Resource Group

Resource Group (RG) – skupina prostředků v subscription.

  • může být vytvořená přes klikání nebo přes command line
  • v jedné subscription může být více resource groups
  • resource group je zdarma
  • typicky rozdělení například na dev / test / prod

Pro každý resource řeším:

  • subscription
  • resource group

SLA = Service Level Agreement – kolik času má být služba dostupná.

Virtual Machines

Po vytvoření VM se na Windows připojím přes Remote Desktop.

Skutečné náklady u VM

  • VM samotné
  • disk
  • public IP
  • storage – bitová kopie systému a všeho kolem

Redukce nákladů

  • autovypnutí – vhodné hlavně pro testovací prostředí
  • reserved instances – vhodné spíš pro produkci

ARM Template

ARM Template – declarative way, tedy popis výsledného stavu. Oproti imperative přístupu typu PowerShell skriptů. Jsou to JSONy s nastavením.

Nasazení třeba přes Cloud Shell – uploadnu parameters.json a template.json.

VM Scale Set

VM se přidávají automaticky podle zátěže z původního image.

  • manual – ručně přidám počet instancí
  • custom – přidám pravidla, minimum a maximum instancí

Azure Instance Metadata Service – API z VM, díky kterému se mohu dotazovat na Azure metadata.

App Services

U App Services nemám přístup k VM. Jen částečně přes konzoli nebo editor online.

Škálování může být ruční nebo přes ruleset.

  • je to jen na nasazení aplikace nebo Docker image
  • má jedinečný název
  • řeší se runtime stack

Sloty

Sloty jsou instance aplikace, aby šlo přenasazovat bez výpadku.

Deployment

  • basic – kliknutím nasadím všechny instance
  • rolling – postupně; další instance se nasadí až po úspěchu předchozí
  • slot po slotu – a můžu přepínat procento zatížení
  • musím podporovat dvě verze současně
  • blue-green – nasadím nové instance pro testery a pak přepnu vše

AKS, ACR, ACI

AKS = Azure Kubernetes Service

  • Vertical scaling – změna výkonu instance, tedy CPU nebo RAM
  • Horizontal scaling – přidání nových instancí kontejneru podle zátěže
  • Azure ACR = Azure Container Registry – úložiště pro kontejnery. Neumí image spustit, jen ho uchovává a poskytuje.
  • ACI – jednoduchá správa jednoho kontejneru.
  • AKS – Kubernetes správa pro více kontejnerů.

V Azure

  • Create → Container Registries
  • RG → Settings → Access Keys – klíč pro remote vkládání image
  • ve VS Code přes Dockerfile build image do Azure, typicky po az login
  • Kubernetes Services → vytvořit Kubernetes cluster

Azure Functions

Azure Functions = serverless. Nemusím řešit server jako takový.

Cold start záleží na hosting plánu.

  • trigger – spouští funkci
  • bindings – spojení funkce s Azure resource, například zápis, spuštění něčeho, výpočet nebo reakce na event

Durable Function je jako dirigent, který řídí, kdy a jak se jednotlivé Azure Functions spustí.

V Azure

  • Function → Create
  • App Service Plan – infrastruktura, na které funkce běží

Networking

  • VNets – virtual networks. Dostanu rozsah IP adres, tedy address space / address range.
  • Subnets – VNet se dělí na více subnetů. Je to část IP rozsahu z VNetu. Subnety spolu mohou defaultně komunikovat, VNety defaultně ne.
  • Load Balancer
  • Application Gateway

NSG

Network Security Group – hlídá inbound a outbound pravidla, tedy takový firewall.

  • inbound rules – tady se například nastavuje RDP port
  • outbound rules

NSG můžu spojit třeba se subnetem.

Peering

Dvě VNet mohou komunikovat spolu. Není to zdarma, typicky centy za GB.

Musím jít do každé VNet a přidat peering.

Network Watcher

Je síťový diagnostický a monitorovací nástroj. Sleduje a analyzuje provoz mezi sítěmi, subnety a virtuálními stroji, včetně provozu mezi různými VNETy přes peering. Umí zobrazit i topologii sítě.

Windows Admin Center (WAC)

Správa VM přes prohlížeč.

Service Endpoint a Private Link

  • Service Endpoint – komunikace VM a resource neprobíhá po internetu, ale po Azure backbone.
  • funguje jen pokud jsou VNet i služba ve stejném regionu
  • Private Link – v podstatě Service Endpoint plus privátní IP adresa služby uvnitř tvé sítě

Zabezpečení přístupu k VM

  • JIT access – dočasný, omezený a auditovaný přístup
  • VPN – omezení například na IP
  • Jumpbox – speciální VM v Azure, které otevírá jediný port směrem ven; přes něj se pak připojuji na ostatní VM, které nemají otevřený port ven
  • Bastion – jumpbox od Azure. Jednodušší a bezpečnější, ale dražší

Load Balancer vs Application Gateway

Load Balancer distribuuje požadavky mezi VM podle health probes.

  • Basic – zdarma, jedna zóna, jen veřejné IP, omezený scale, omezená podpora scale set VM; vhodné spíš jen na vývoj a testy
  • Standard – placený, funguje napříč zónami

Application Gateway – load balancer plus reverse proxy, která rozumí HTTP/HTTPS provozu. Má i Web Application Firewall a může obsluhovat více backendů ve stejné VNet.

Databáze

  • databáze na VM – musím se starat o všechno sám
  • Azure SQL

Azure SQL

  • Azure SQL Database – jedna databáze na serveru jako služba, tedy PaaS
  • Provisioned – stálý, rezervovaný výkon
  • Serverless – pay-as-you-go
  • Elastic Pool – více databází na jednom serveru, sdílený výkon
  • hodí se, když mají různé databáze rozdílné peaky
  • Managed Instance – podpora věcí, které znáš z on-premise SQL Serveru, vhodné třeba při migraci

Nastavení otevřenosti řeším přes firewall a připojení přes connection string.

Cosmos DB

NoSQL databáze s velmi dobrým výkonem.

  • přes různá API rozhraní, například SQL nebo Mongo
  • consistency level – jak rychle jsou data synchronizovaná mezi regiony a jaký může být lag
  • vytvořit account → potom databázi → Data Explorer → new container

Azure Database for MySQL

Nemám přístup k OS, jen k databázi. Je to PaaS. Azure řeší zálohy a škálování.

  • Azure Database for MySQL – Flexible Server
  • MySQL Server – Azure Arc – napojení na on-premise databázi se správou a monitoringem přes Azure
  • podobně i PostgreSQL a další

Azure Storage

Blobs, Files, Queues, Tables, Disks.

  • blob – soubory
  • file – sdílené soubory
  • queues – messaging
  • tables
  • disks – disky VM

V Azure: Storage Account → Add Container.

  • připojení přes connection string, key nebo Shared Access Signature
  • mohu nastavit CDN, pravidla pro archivaci a mazání
  • mohu použít desktop Azure Storage Explorer

Azure Redis

Rychlá distribuovaná in-memory cache. Data jsou jen v RAM.

Messaging

Azure Storage Queue

Jednoduchá fronta. Levné a jednoduché úkoly, například e-maily nebo notifikace.

  • max size 64 KB
  • create / send / receive

Azure Service Bus

Enterprise message broker pro komplexní integrace, routing, transakce a topic/subscription model.

  • posílání dat, příkazů nebo requestů
  • consumer zprávu zpracuje, například objednávku
  • drží pořadí ve frontě
  • dead-letter queue

Azure Event Grid

Eventing, tedy notifikace o změnách. „Něco se stalo.“

  • publisher → event source → event grid topic → event handler
  • nedrží pořadí ve frontě

Azure Event Hub

Datový streaming. Obrovské množství dat, například telemetrie, IoT, logy nebo senzory.

Azure AD / Azure Entra

Řeší práva uživatelů, role a skupiny.

Typy autentizace

  • něco, co znáš
  • něco, co máš
  • něco, co jsi

Security Defaults – přednastavené bezpečnostní mechanismy, například MFA.

RBAC

Role Based Access Control – uživatel má roli a role určuje, co může dělat.

  • Owner – může dělat vše v daném scope
  • Reader – jen čtení
  • Contributor – může dělat vše kromě přístupů

Nastavení: Access Control (IAM) → Role Assignments.

Managed Identity

Každá aplikace může mít zapnutou identitu, aby se mohla bezpečně autentizovat vůči jiným Azure službám.

Azure AD B2C

Azure Active Directory Business-to-Consumer. Používá se pro přihlašování běžných uživatelů, tedy zákazníků, klientů, občanů nebo studentů, do mojí aplikace.

Monitoring

Monitoring section v menu:

  • metriky
  • logy
  • alerty – custom notifikace

Log Analytics Workspace

  • vytvořím Log Analytics Workspace
  • vyberu scope, tedy resource
  • v resource musím nastavit Activity Logs → Export Activity Logs → Add Diagnostic Settings
  • tím pošlu logy i do vytvořeného Analytics Workspace

Logs v menu řeší totéž, ale pro konkrétní resource.

  • Insights – třeba Application Insights
  • Monitor – všechny metriky, logy, insights a podobně v předplatném
  • Application Insights – například Availability test dostupnosti aplikace

Tag

Tagy jsou kvůli organizaci, správě nákladů a automatizaci. Je to přiřazení key:value k resource.

Security

Security = identita mezi resources a obecně zabezpečení přístupů.

  • VM – otevřít jen porty, které chci, ideálně jen pro konkrétní IP, případně přes Bastion
  • VNet – NSG, peering
  • DB – šifrování, VNet připojení, public/private endpoint, firewall rules
  • App Service – nevystavovat přímo internetu, použít Application Gateway, Entra AD a MFA

Key Vault

Do Key Vaultu si ukládám secrets, klíče a další citlivé věci.

Mohu nastavit start i expiraci klíčů.

Typicky si nastavím roli Vault Secrets Officer.

Name: ConnectionStrings--BooksDb
Value: default connection string value
"KeyVault": {
  "BaseUrl": "https://my-keyvault.vault.azure.net/"
}

V appsettings si dám Key Vault URL a v Program.cs to načtu a zaregistruji.

Takhle je to hlavně pro cloudové Azure aplikace.

Defender for Cloud

Dříve Security Center, dnes Defender for Cloud.

  • recommendations – doporučení
  • inventory – resources, na které se Defender dívá podle předplatného

Disaster Recovery

DR = Disaster Recovery – plán pro případ, kdy se kompletně zavře region.

  • RPO – tolerance ztráty dat, tedy kolik dat ztratím za poslední čas od replikace
  • RTO – za jak dlouho naskočí služby

Směrování provozu při DR

  • Traffic Manager – starší DNS-based směrování
  • Front Door – moderní globální edge brána, CDN, nejbližší zdroj; typicky Front Door → App Gateway → Resource

Náklady v Azure

Azure Cost Management – faktury, platby za služby, predikce, kolik budu platit.

Azure Policy

Služba v Microsoft Azure, která slouží k automatickému řízení a vynucování pravidel.

  • například každý Storage Account musí mít zapnuté šifrování
  • Public IP adresy se nesmí vytvářet

Obecně

  • Subscription – Settings → Resource Providers – registrace služeb pro danou subscription
  • VM – když ji stopnu, typicky neplatím compute; jiné věci ale platit můžu dál
  • App Service – neplatím jen když ho smažu

Další služby

  • IoT Hub – message broker mezi miliony zařízení a cloudovou aplikací
  • Notification Hub – posílání notifikací na mobilní zařízení, weby a aplikace
  • Azure Arc – umožňuje propojit on-premise nebo jiné cloudy
  • Azure Advisor – osobní konzultant, který analyzuje prostředí a dává doporučení na výkon, optimalizace a náklady
  • Advisor Score – celkové zdravotní skóre prostředí v procentech
